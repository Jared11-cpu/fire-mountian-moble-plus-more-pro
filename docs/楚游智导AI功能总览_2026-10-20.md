## 0. 一页读懂

**产品**：面向游客、景区、民宿和文旅部门的湖北文旅 AI 智能体。游客用一句话说需求，系统用高德查真实地点、用千问理解需求并排序解释，生成可执行的行程、路线、餐饮和预算方案；商家可以生成住客服务内容；还有旅行手账、天气、交通对比、分享链接和文旅看板。覆盖六城：武汉、宜昌、恩施、荆州、襄阳、黄石。

**三条原则**（贯穿所有功能）：
1. 事实来自高德或用户输入，模型只负责理解、排序、解释，不能编造地点、价格、营业时间。
2. 区分"真实查询""规则估算""演示数据"，页面上要如实标出。
3. 手账等用户数据只存本机，没有账号和云同步。

**数据可信度速查**

| 功能 | 数据来源 | 属于 |
| --- | --- | --- |
| 景点、餐厅、地点详情 | 高德 POI 接口 | 真实查询 |
| 路线、距离、时长、道路几何 | 高德路径规划 | 真实查询（失败时降级为估算并提示） |
| 需求理解、候选排序、分析文案 | 千问（百炼） | AI 生成，事实受上面两项约束 |
| 到达时间排程 | 千问，失败则服务端规则 | AI 或规则，页面标明来源 |
| 餐饮费用 | 餐厅人均中位数 × 餐数 | 估算 |
| 门票、住宿、城际交通价格 | 无真实报价接入 | 缺失，页面列为"缺失费用" |
| 天气 | Open‑Meteo 7 天预报 | 真实查询，非官方预警 |
| 交通"实时查询" | 此刻重新查询路线 | 不是车辆 GPS 或到站 |
| 文旅看板 | `mockData.ts` | 演示数据 |
| 商家规则模板 | 本地模板 | 示例，点生成才走真实链路 |

## 2. 规划流程（核心功能）

### 2.1 用户操作
输入框写一句话（例："恩施三天两夜，预算1000元，喜欢峡谷和拍照，不吃辣"）→ 点"识别这句话"确认识别出的标签 → 补充表单：出发地、人群（学生/朋友/家庭/情侣/老人）、天数、预算、起止日期、兴趣（美食/拍照/自然风光/历史文化/Citywalk）、饮食限制（不吃辣/素食）、特殊需求（带儿童/行动不便/雨天方案）→ 点"生成我的 X 行程"。

出发地有三种来源：示例站点（默认，如宜昌东站）、手动输入后经高德地理编码确认、浏览器定位（WGS84，后端或浏览器各转换一次为高德坐标）。拒绝定位或超时时出发地不变并提示。

### 2.2 生成链路（`tripStore.generateFromText`）
```
用户输入
 → ① 理解需求      POST /api/ai/parse-request（千问）+ 本地规则合并
 → ② 检索真实景点  GET  /api/attractions/search（高德，多关键词并发）
                   POST /api/ai/recommend（千问在真实候选中排序，ID 必须来自候选）
 → ③ 餐厅、排程、分析（并行）
      POST /api/restaurants/guide  沿最终路线查周边真实餐厅并排序
      POST /api/ai/schedule        07:30–21:30 安全排程
      POST /api/ai/analyze         带路线、餐厅人均、预算分配，回答预算够不够、兴趣满足没
 → 只有真实地点和 AI 分析都返回，才发布方案；失败不展示规则占位方案
 → 地图请求真实道路
```
规则草稿 `generateTripPlan` 只在内部用来铺底，**不会当最终结果展示**。

### 2.3 进度、取消、超时（本轮新增和加强）
- 规划页显示三步进度（理解需求 / 检索真实地点 / 餐厅、分析与排程）、已用时间和"取消生成"按钮。
- **整次生成 90 秒总期限**：超时中止所有在途请求，提示"停在哪个阶段"，当前方案保持不变。
- 取消或被新的生成取代后，迟到的旧结果不会覆盖新方案；识别结果也不会写回输入框。
- 有限重试：网络失败或遇到 408、425、429、503 时重试一次；500、502、504 等不立即重试，避免多等一轮。

### 2.4 排程的安全边界（本轮修复）
- AI 排程必须通过校验：覆盖全部点位、天数一致、到达时间在 07:30–21:30、同天顺序递增且留足停留和交通时间。
- AI 失败、超时或未通过校验时，服务端改用规则排程。**规则排程同样遵守 21:30**：装不下的点位不给伪造时间，返回 `status=infeasible`、每天哪些点位放不下，以及"删减、缩短停留或移到其他天"的建议；以前会排出 22:00 以后或压成 23:59。
- 未配置千问 Key 时返回 503，不假装成功。
- 页面"数据来源与可信度"面板显示排程来源（千问 / 规则）和不可行提示。

## 3. 方案页（地图工作台 `MapWorkspace`）

左侧一排图标页签，右侧是地图和详情。手机上详情是可上滑的底部面板。

| 页签 | 内容 |
| --- | --- |
| 概览 | 方案标题与摘要、**数据来源与可信度面板**、点位数和时长可直接编辑、**实际路线距离（只读，来自高德道路）**和"期望距离上限"（可编辑）、出发日期（过期会提示） |
| 路线 | 逐站列表：到达时间、停留、交通耗时、配图、景点详情链接（高德、携程）、点位备注，可调整点位数 |
| 行程记录 | 每日记录，勾选已完成景点，写当时的详细记录，上传照片，进入手账 |
| 天气 | Open‑Meteo 当前天气、8 小时曲线、出行建议、**按行程日期显示的预报** |
| 交通 | 公交、地铁、步行、驾车方案对比，真实/估算标记，查询时间 |
| 美食 | 沿路线的真实餐厅：人均、距离最近点位、推荐理由、点评搜索链接 |
| 预算 | 预算总额、各项分配、增减和超出提示 |

### 3.1 地图 `RouteMap`
- 高德 JS API 2.0 绘制点位和道路。道路几何优先走后端 `/api/route/plan`，失败时用浏览器 `AMap.Driving` 备选。
- 两条通道都失败：保留点位和底图，明确提示"真实道路不可用"，**不把直线冒充道路**。
- 坐标：定位得到 WGS84；后端 `routeCoordinate` 或浏览器 `AMap.convertFrom` 各自只转换一次；手动输入的出发地和高德 POI 本来就是 GCJ02，不转换。
- 地图用 Marker 和道路，切换点位高亮。需要真实 JS Key 与域名白名单才能在浏览器里加载。

### 3.2 交通 `transportService`
- 提供三种模式：规则引擎（离线估算）、后端 `/api/route/plan`（真实道路）、`/api/transit/plan`（公交换乘）。
- `live-query` 表示"此刻重新查询了路线"，**不是**车辆 GPS 或列车位置；`/api/health` 明确返回 `vehicleRealtime=false`。
- 可配置 `VITE_TRANSPORT_API_URL` 接入你自己的交通后端，不得把供应商私钥放进浏览器。

### 3.3 配图 `pointImageService`
先用本项目精选封面，再按需用高德地点相册，再用 Wikimedia Commons；每张图带来源和作者。
精选封面共 42 张原本直接外链维基图片库，国内访问慢；2026-10-21 已镜像到本站 `public/photos/`（映射表 `src/data/commonsMirror.json`，取图函数 `commonsImageUrl`），没镜像到的仍回退到原外链。按需动态检索到的维基图片仍走外链。

### 3.4 天气（本轮修复）
- 以前永远显示"从今天起的前几天"并标成第 1、2 天，行程在两周后也一样，日期是错的。
- 现在按**行程起止日期**匹配 Open‑Meteo 的 7 天预报：超出范围或日期已过，明确写"没有这几天的预报"；只覆盖一部分，提示"仅覆盖前 N 天"。
- 缓存键带坐标，换起点或城市不会读到别处的预报；缓存 30 分钟，请求 8 秒超时，失败可重试。
- 它不是官方气象灾害预警。

### 3.5 预算和费用口径（本轮新增展示）
- 预算分配按总预算比例拆分，是**计划额度，不是实际价格**。
- "数据来源与可信度"面板分三栏：
  - **已知费用**：点位上已有明确价格的项目；
  - **估算费用**：餐饮 = 路线周边真实餐厅人均中位数 × 餐数，并提示是否高于餐饮额度；
  - **缺失费用**：没有价格的门票、没有价格的餐饮、住宿和城际交通（未接入真实报价）。
- 同时展示 AI 分析返回的"假设"和"数据缺口"，以前这两项被丢弃。
- 没有价格数据时不会断言"预算一定够"。

## 4. 手账

- 入口：方案页"行程记录"和 `/journal`。
- 记录内容：景点、日期、备注、照片（压缩为最长边 1920 的 WebP，单张原图上限 10MB）、位置。
- **存储在本机浏览器**：记录元数据在应用状态（localStorage），照片在 IndexedDB。没有账号，也没有云同步；清理浏览器数据会丢失。
- 水彩路线海报：把已完成景点绘制成图片并保存。
- **备份手账 / 恢复备份（本轮新增）**：导出一个 JSON，含记录和照片；导入时先校验（坏文件、别的程序导出的文件、更新版本的文件都会被拒绝，本机数据不动），同 id 记录保留本机版本，照片缺失会如实报告。
- 分享链接只编码方案，不包含照片和真实足迹。

## 5. 商家后台

- 输入：商家名称、城市、周边景点（最多 4 个）、目标客群。
- 页面初始显示的是**规则模板示例**（明确标注），点"生成住客服务方案"才走真实链路。
- 链路：`BusinessPage` → `businessApi` → `POST /api/business/plan` → `server/guide/business.js`：
  1. 对每个景点关键词用高德检索，**只接受同城且名称匹配的候选**，重名的外地景点算"未找到"；
  2. 以前两个已核实景点为中心检索 2 公里内真实餐厅并去重；
  3. 千问基于这些事实生成：一日游路线、欢迎语、入住提醒、周边美食、短视频脚本、小红书文案、客服回复；
  4. **事实校验 `factCheck.js`（本轮新增）**逐行逐句检查：未经高德核实的地点、不在高德人均消费里的价格、电话号码、门票和营业时间，全部移除并记录原因；被删空的栏位只用已核实事实补齐。
- 页面如实显示：未找到的景点、周边餐厅是否核实、被移除的条数和首条原因。
- 请求 60 秒超时，可取消，离开页面自动中止。
- 高德未配置或调用失败时，如实返回对应错误，不再误报"找不到景点"。
- AI 失败时降级为规则模板并明确提示，不冒充 AI 结果。

## 7. 后端接口（`server/index.js`）

同一份代码，三种运行方式：Sites Worker（`ASSETS` 提供静态页）、Node 进程（`server/node-entry.js`，ECS 用）、Vercel 代理（只转发，不运行 server）。统一 CORS 和来源校验，请求体有大小上限。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/health` | 配置状态（ai、aiProvider、amap、vehicleRealtime=false）和 **build.sha / builtAt（本轮新增）** |
| GET | `/api/showcase/wuhan` | 首页展示配置 |
| POST | `/api/ai/parse-request` | 自然语言提取城市、天数、预算、兴趣等 |
| POST | `/api/ai/recommend` | 在真实候选中排序，ID 必须来自候选 |
| POST | `/api/ai/analyze` | 方案分析，返回 analysis、assumptions、dataGaps |
| POST | `/api/ai/schedule` | 安全排程（含规则降级和 infeasible） |
| POST | `/api/ai/transport-advice` | 交通方案解释 |
| GET | `/api/poi/search`、`/attractions/search`、`/restaurants/search`、`/shops/search`、`/hotels/search` | 高德 POI |
| GET | `/api/location/reverse`、`/location/geocode` | 逆地理、地理编码（支持 `coordsys=gps`） |
| POST | `/api/restaurants/guide`、`/shops/guide`、`/guide/recommend` | 先高德查事实，再千问排序，保留真实候选 ID |
| POST | `/api/business/plan` | 商家住客服务方案（含事实校验） |
| POST | `/api/route/plan` | 驾车、公交、步行、骑行路线，返回道路几何 |
| GET | `/api/traffic/status` | 路况 |
| GET | `/api/transit/realtime`、POST `/api/transit/plan` | 公交实时查询（非车辆 GPS）和换乘 |

高德服务端请求有排队和限流重试（本轮新增，遇 QPS 超限码会等待后重试）。千问单次上游超时 25 秒。

## 8. AI 与地图配置

| 变量 | 位置 | 作用 |
| --- | --- | --- |
| `AI_PROVIDER` | 后端 | 目前 `qwen` |
| `DASHSCOPE_API_KEY` | 后端 | 百炼密钥，永远不加 `VITE_` |
| `AI_BASE_URL` / `DASHSCOPE_WORKSPACE_ID` | 后端 | 百炼地址和业务空间，需与地域配套 |
| `AI_EXTRACT_MODEL` / `AI_RECOMMEND_MODEL` | 后端 | 默认 `qwen-flash` / `qwen-plus` |
| `AMAP_WEB_SERVICE_KEY` | 后端 | 高德 Web 服务 Key（POI、路线、路况） |
| `ALLOWED_ORIGINS` | 后端 | 额外允许的前端来源，逗号分隔 |
| `HOST` / `PORT` | Node 入口 | 默认 `127.0.0.1:8787` |
| `API_BUILD_SHA` / `API_BUILT_AT` | 后端 | 非敏感版本信息，`/api/health` 返回 |
| `VITE_AMAP_ENABLED` / `VITE_AMAP_KEY` / `VITE_AMAP_SECURITY_CODE` | 前端构建 | 浏览器地图（JS API），**会进入浏览器产物**，必须配域名白名单 |
| `VITE_API_BASE_URL` | 前端构建 | 后端地址，同域留空 |
| `VITE_TRANSPORT_API_URL` | 前端构建 | 可选的自有交通后端 |
| `VITE_BASE_PATH` | 前端构建 | 基础路径，默认 `/` |
| `BUILD_SHA` | 前端构建 | 写入页面 `<meta name="chuyou-build-sha">` |

高德有两类 Key，互相不能代替：浏览器地图用"Web 端（JS API）Key + 安全密钥"，后端用"Web 服务 Key"。Node 入口只读 `process.env`，不会自动读取项目里的 `.env.local`（本地 `pnpm run start:server` 用 `--env-file-if-exists` 读取）。

## 9. 部署拓扑

```
浏览器 → https://cwychuyouai.online
   ├─ /       静态前端
   └─ /api/*  同域后端 server/index.js → 高德、百炼
另有：Sites  https://chuyou-ai-250.galangalheli826.chatgpt.site（Worker 运行同一份 server）
      Vercel 代理 api/router.js（默认转发到 Sites，具体生产域名未确认）
      GitHub Pages 静态前端（无后端）
```
